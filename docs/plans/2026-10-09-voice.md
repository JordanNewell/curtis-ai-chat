# Voice v2 — scope (2026-10-09)

> Thesis: the player is already good; the **voice is the product**. Voice v2 makes the voice chosen, persisted, and genuinely listenable — system-voice control first, neural TTS second, a local offline voice as the flagship. No new playback UI paradigm; the sentence player earns new superpowers instead.

What ships, in one line each: pick your voice (settings, persisted), watch what you hear (karaoke highlight), hear a neural voice (OpenAI, key you already have), hear it offline (Kokoro-82M, in-renderer, no key), and point dictation anywhere (Groq/custom Whisper endpoints).

## What already exists (and the gaps this fills)

| Piece | State | Gap voice v2 fills |
|---|---|---|
| TTS player (`src/chat/tts-controller.ts`) | Sentence-chunked playback: pause/resume, skip ±1, rate cycle 1→2, stale-event generation tag | Rate resets to 1 every `play()`; voice is a hardcoded heuristic (`pickVoice()`, line 57: en-US default → any en → first); no settings anywhere |
| Speak action + player UI (`src/chat/view.ts:1913`, `:1963`) | Per-message hover action, inline player bar, one controller per play | No highlight of the sentence being read; controller constructed per play reads nothing from settings |
| Auto-speak (`src/chat/view.ts:2060`) | Toggle in the input row → simple `speakText()` path (`src/chat/voice.ts:68`) | Session-only (lost on restart); bypasses the controller entirely, so engine upgrades won't reach it unless unified |
| Markdown stripping (`src/chat/voice.ts:51`) | Code fences → spoken as literal "code block", links/headings/list markers cleaned | Reading code aloud at all is wrong for listening; no way to skip it |
| STT (`src/chat/voice.ts:15`) | MediaRecorder → `api.openai.com` + `whisper-1`, hardcoded; key via `resolveOpenAiBearerToken()` (`view.ts:1828`, private, OpenAI-only) | No endpoint/model choice (Groq's `whisper-large-v3-turbo` is far cheaper/faster at the same API shape); no auto-send after dictation |
| Settings (`src/settings.ts`, declarative `getSettingDefinitions()`) | Rich groups (autocomplete at `:1032` is the pattern: `this.row()` + Setting + dropdown/slider/toggle) | Zero voice fields in `CurtisSettings` (`src/types.ts:364`) |

Positioning: playback mechanics are a solved internal problem — everything below is voice quality, user control, and backends behind the existing player.

## Redundant or useful?

**A voice picker alone is table stakes** — every TTS surface has one, and system voices are the ceiling of that feature. The spec earns its size from the ladder above it:

1. **Persisted control (P1)** — the user's voice/rate/auto-speak survive restarts. Unsexy, unskippable.
2. **Neural TTS on the existing key (P2)** — OpenAI `/v1/audio/speech` is a dramatically better voice for pennies, and Curtis already holds the key for Whisper. One dropdown, no new onboarding.
3. **Local neural voice (P3)** — Kokoro-82M in the Electron renderer: the "sounds great, no key, never leaves the machine" option. Vendor-hosted chat apps structurally cannot ship this; it's the same privacy play as the local-only agent.
4. **Dictation anywhere (P4)** — endpoint/model/key configurability rides one signature change.

**Internal redundancy check:** P2 and P3 share one backend abstraction — build the interface once in P2, P3 is a second implementation plus loader. Auto-speak unifies onto it in P1 so no path is left behind.

## Attack plan

### P1 — Control, persistence, karaoke (the bulk of the perceived win)

- `src/types.ts`: `ttsVoiceUri: string` (`''` = auto), `ttsRate: number` (1), `ttsPitch: number` (1), `ttsAutoSpeak: boolean` (false), `ttsHighlight: boolean` (true).
- `src/chat/tts-controller.ts`: constructor takes `config: { voiceUri, rate, pitch }` read from settings at play time (per-play construction stays); `play()` keeps the configured rate instead of resetting to 1; `pickVoice()` matches `voiceURI` first, falls back silently to the existing heuristic when the stored voice isn't on this machine (voices are platform-specific; no error, just fallback).
- `src/chat/voice.ts`: `speakText()` takes the same config (auto-speak path).
- `src/chat/view.ts`: `autoSpeak` initializes from settings; `toggleAutoSpeak()` persists; a single `getTtsConfig()` helper feeds controller + speakText.
- **Sentence source flips to the DOM** (the karaoke enabler): export `splitIntoSentences`; the view walks the rendered message body (TreeWalker over text nodes, skipping `pre`/`code`/action bars/player) and hands `play()` a pre-split `string[]`. Fallback to `cleanTextForSpeech(content)` splitting when no DOM (programmatic triggers). One source of truth → highlight indices can't drift; side effect: code stops being read aloud as "code block" (an improvement, note in changelog).
- **Highlight:** wrap each sentence range in `<span class="ai-tts-sent">`; the existing `subscribe()` callback toggles `.is-active` on `currentSentence` + `scrollIntoView({ block: 'nearest' })`. Gated by `ttsHighlight`.
- `src/settings.ts`: **Voice** group — Auto-speak (toggle), Voice (dropdown from `getVoices()` + "System default"; re-populate on `voiceschanged`), Rate (slider 0.5–2, step 0.25; player's rate cycle stays a session-level override on top), Highlight (toggle).
- Tests: `splitIntoSentences` + config resolution + (now possible) controller flow with a fake backend — `tts-controller.ts` is already Obsidian-free; the backend seam keeps it that way.

### P2 — Neural voice via OpenAI (one dropdown away)

- `src/types.ts`: `ttsEngine: 'native' | 'openai'` (default `'native'`), `ttsOpenAiVoice: string` (`'alloy'`; options: alloy, ash, ballad, coral, echo, fable, onyx, nova, sage, shimmer), `ttsOpenAiModel: string` (`'gpt-4o-mini-tts'`), `ttsOpenAiStyle: string` (`''` — optional `instructions` param; the model is steerable: "warm narration", "explain like a colleague").
- New `src/chat/tts-backends.ts`: `TTSBackend { speak(sentence: string): Promise<void>; cancel(): void }`.
  - `NativeSpeechBackend` — wraps the current utterance logic, moved verbatim.
  - `OpenAiSpeechBackend` — `window.fetch POST /v1/audio/speech` `{ model, voice, input, response_format: 'mp3', instructions? }` → blob → object URL → `Audio`. Rate via `playbackRate` client-side (no API `speed` param — works identically for both engines). **One-sentence prefetch** while the current plays to hide per-chunk latency; LRU cache (~20 entries, keyed voice|model|sentence) so skip-back replays instantly.
- `TTSController` takes a backend from a factory keyed on `ttsEngine`.
- Key: extract the bearer resolution from `view.ts:1828` into a shared helper (mic + TTS both use it); missing key → Notice + native fallback, not a dead player.
- Failure posture: any non-OK/network error → one Notice ("Neural voice unavailable — using system voice for this session") + session fallback flag. Auto-speak on the neural engine gets the same fallback.
- Settings rows: Engine dropdown, OpenAI voice dropdown, Reading style text, with the description saying plainly: uses your OpenAI key, billed per character.

### P3 — Kokoro-82M local (desktop flagship, riskiest)

- `ttsEngine: 'kokoro'` — **desktop only**; the settings row and engine resolve to native on mobile / when `navigator.gpu` is absent and WASM is too slow.
- **Delivery: bundled npm deps, remote weights.** `kokoro-js` + `@huggingface/transformers` as pinned dependencies; `KokoroTTS.from_pretrained('onnx-community/Kokoro-82M-v1.0-ONNX', { dtype: 'q8', device: webgpu|wasm })`. Bundled code keeps the supply chain pinned and sidesteps Obsidian's CSP on remote scripts — the parts that can't bundle (ORT wasm, ~80–90MB q8 weights) are fetched from CDN by transformers.js at first use and cached in browser storage, which is the proven pattern (transformers.js-based Obsidian plugins run today). Accept the main.js weight; measure at kickoff, revisit only if it's egregious.
- `KokoroSpeechBackend` implements the P2 interface: `generate(text, { voice, speed })` → WAV blob → same Audio path; reuses the prefetch/cache pipeline.
- First-use UX: progress Notice from the loader callback ("Downloading voice model — one time, ~90MB"), then silent.
- Voices: ~54 built-ins (`af_heart`, `af_bella`, `am_michael`, `bf_emma`, …) — dropdown populated from `tts.voices` after load, static popular subset before.
- Singleton TTS instance; disposed on engine switch and `onunload`.
- Known risks, stated: slow first load on cold storage; WASM fallback can be slower than realtime on long messages (prefetch masks it; description warns); if ORT/WebGPU init throws → Notice + native fallback, same posture as P2.

### P4 — Dictation anywhere (small)

- `src/types.ts`: `sttBaseUrl: string` (`''` = OpenAI default), `sttApiKey: string` (`''` = reuse OpenAI key), `sttModel: string` (`'whisper-1'`), `sttAutoSend: boolean` (false).
- `transcribeAudio(blob, bearer, baseUrl, model)` — signature change; view passes settings. `window.fetch` stays (requestUrl still lacks multipart).
- Settings rows under Voice: Endpoint (OpenAI / Groq / custom), Custom base URL (text), Model (text), Auto-send after dictation (toggle). Groq preset fills `https://api.groq.com/openai/v1` + `whisper-large-v3-turbo`.
- `sttApiKey` empty + endpoint ≠ OpenAI → clear error naming the field.

### Docs & release (per phase)

- `docs/VOICE.md` rewritten per phase; `docs/INDEX.md` line updated when neural/local ships ("Whisper STT + browser TTS" → the fuller story); CHANGELOG entries under the next minor (2.1.0 target); release notes terse, no emoji (hard constraint). `minAppVersion` untouched — declarative settings already require 1.13.0.

## Open decisions

1. **Sentence source:** DOM-walk (recommended — highlight can't drift, code silenced) vs. content-split with fuzzy DOM alignment (keeps `play(text)` signature, drift risk).
2. **Rate semantics:** settings value = default, player cycle = session-only override (recommended) vs. player cycle writes back to settings.
3. **Kokoro bundle weight:** bundled deps (recommended, pinned, CSP-safe) vs. CDN-imported library (leaner main.js, unpinned, CSP gamble). Decide at P3 kickoff with a real measurement.
4. **Auto-speak:** unify on the backend abstraction in P1 (recommended — engines reach every path) vs. leave the simple path native-only.

## Fences — not building

- **Voice cloning / ElevenLabs** — premium-tier material; MONETIZATION.md territory, not the free plugin.
- **Realtime/websocket streaming TTS** — sentence prefetch gets latency low enough for read-aloud; a socket transport is a different reliability budget.
- **Local STT** — 40MB+ of whisper.cpp for marginal gain when Groq-turbo is one endpoint field away.
- **Conversational voice mode** (barge-in, VAD loop, the ChatGPT voice experience) — different product.
- **Audio export** (save narration as attachment) — no demand signal; the vault is for text.
- **Per-conversation TTS settings** — global only in v1, like every other voice knob.

## Sizing

P1 ~1 focused session; P2 ~1 (backend seam does double duty for P3); P3 ~2–3 (bundle measurement, loader, fallback posture); P4 ~half. Ship P1 alone as the quick win; P2 rides the next minor; P3+P4 close it out.
