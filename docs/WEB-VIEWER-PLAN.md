# Curtis Web Viewer — Export to Static HTML / Share Link

> Task fleet-cabinet #715 / BIG LOOP #710. Status: plan (scoped 2026-10-10).
> Owner: Lucy (architecture). Implementation: Kate (HTML theme/craft) + Cameron (export engine).

## 0. What exists today

`src/chat/export.ts` exports a conversation as **markdown only** (`/export` slash command, browser download). No HTML, no share link. Images export as vault-path references — broken outside Obsidian. That's the gap.

## 1. Product shape — two formats, one engine

**Format 1: single-file static HTML (v1, the core deliverable).**
One `.html` file: markdown rendered at build time to static markup, CSS inlined, images embedded as data-URIs (with a size cap + "omit images" toggle). Fully offline, openable anywhere, email-able.

**Format 2: share link (v2, deferred until v1 proves demand).**
Hosted upload is a privacy inversion for a local-first product. v2 path: one-click "publish to GitHub Pages" (user's own repo) or a self-host script — **no first-party hosted service in v1 or v2 without Jordan explicitly choosing to run one.** The "viral loop" ambition is noted but privacy default wins.

## 2. Export engine

- Build on the existing `formatConversationAsMarkdown` pipeline: same conversation model, same metadata block, then render MD → HTML with the plugin's existing markdown renderer (the message-renderer already does this for the sidebar — reuse, don't add a second renderer).
- Sanitize ruthlessly: rendered HTML is static content from model output — apply the same sanitization the sidebar uses. No script tags in output, period.
- Wiki compilation (v2): `curtis export --wiki <folder-or-note>` walks linked notes via the existing `@`-mention/link graph and produces the same single-file site with an internal nav. Reuse RAG index adjacency, no new traversal code.

## 3. Zero-tracker guarantee (hard constraint)

- Output contains **no** analytics, beacons, fonts, or any external requests. System fonts only (matches Curtis brand type anyway).
- Add a CI check: exported fixture must make 0 network requests (headless smoke asserts no `http(s)://` src/href except `#` anchors) — makes the guarantee testable, citable in the privacy doc.
- Badge is text+inline-SVG only.

## 4. Theming

Three themes, honoring the brand system (Kate's lane): `curtis-dark` (default), `curtis-light`, and `paper` (print-friendly). Theme picker at export time; output hardcodes the choice. `prefers-color-scheme` NOT auto-honored — the exporter's choice is the share's presentation.

## 5. Badge spec

Footer badge on every export: inline SVG lockup — "Generated by Curtis AI" + link to the product site. Inline (no remote image), one link, `rel="noopener noreferrer"`. Users may remove it by editing the HTML (we don't booby-trap), but it ships by default — that's the viral loop that survives the zero-tracker constraint.

## 6. UI/CLI hooks

- Sidebar: expand `/export` → modal: HTML (default) / Markdown / theme / include-images toggle → download.
- Message actions: "Share this reply" → same modal scoped to one exchange.
- CLI (#714): `curtis export [conversation] --html --theme dark` once CLI Phase C lands — engine is shared, CLI is a thin flag wrapper.

## 8. Risks

- **Secrets in transcripts** — exporter must redact OS-keychain-referring config blocks; add a "scan for API keys" pre-export lint (reuse gitleaks-style patterns) with a warning, not a block.
- **HTML size explosion** from data-URI images — cap + toggle (Phase C exists for this).
- **Share-link scope creep** — the "hosted link" version is a service with obligations (abuse, takedowns, retention). Not eng's call to start one; flagged for Jordan/Miranda if metrics ever justify it.
